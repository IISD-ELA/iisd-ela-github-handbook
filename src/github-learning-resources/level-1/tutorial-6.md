# Tutorial 6 — Managing repository access and permissions

&nbsp;&nbsp;&nbsp;When you submit a project through our submission system, you have the option to specify which IISD-ELA GitHub teams should have access to your repository and their permission levels. By default, **Admin** permissions are also granted to your own GitHub account and the **DB Admin** team (IISD-ELA data team), so they can provide ongoing support and maintenance.

**1. Viewing and changing repository permissions**  
&nbsp;&nbsp;&nbsp;If you need to add collaborators, change team permissions, or remove access after your repository has been created by our submission system:

1. Open your repository on GitHub
2. Navigate to **Settings** > **Collaborators & Teams**
3. Review the teams and individuals who currently have access.
4. Use **Add teams** or **Add people** to grant access, or modify existing permissions.

&nbsp;&nbsp;&nbsp;For a list of all IISD-ELA GitHub teams and who they are, see [Appendix 3 - Teams section](../appendices/teams.md#3-teams).

**2. Choosing appropriate permissions**  
&nbsp;&nbsp;&nbsp;You can choose from **Read** (can only look at the project but cannot change any files, code, or settings); **Write** (can actively work on the project, push code, create new branches, and edit files); **Maintainer** (can manage daily workflow of the project, in addition to write permissions); **Admin** (has total control over the repository, including settings and security).

&nbsp;&nbsp;&nbsp;Avoid granting **Admin** permissions unless necessary. Whenever possible, grant access through IISD-ELA GitHub teams rather than individual accounts to simplify permission management. Again, for a list of all IISD-ELA GitHub teams and who they are, see [Appendix 3 - Teams section](../appendices/teams.md#3-teams)
