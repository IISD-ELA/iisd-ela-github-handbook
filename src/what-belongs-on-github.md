# What belongs on the IISD-ELA GitHub?
&nbsp;&nbsp;&nbsp;GitHub is widely known as a platform where developers store their software code. However, at IISD-ELA, **we encourage you to upload any work that could benefit from being preserved, organized, shared, or having its changes tracked over time**.

&nbsp;&nbsp;&nbsp;Your project doesn't need to involve programming, be actively developed, or collaborative. Even completed projects, one-time analyses, and documentation only resources can benefit from being stored on GitHub. You never know who might benefit from your work in the future, which is why we encourage preserving and sharing work that might otherwise be forgotten.

### What can be uploaded on GitHub
&nbsp;&nbsp;&nbsp;Below are some examples of projects that you are encouraged to upload on GitHub. This is only a set of examples and not an exhaustive list.  
|Project Type | Examples
|---|---|
|**Data analysis** | R/Python scripts, statistical/exploratory analyses, Jupyter notebooks |
|**Data visualization** | Scripts for generating figures, maps, interactive dashboards |
|**Data processing and QA/QC**| Data cleaning scripts, validation procedures, reuseable processing workflows |
|**Scientific methods and procedures** | Standardized calculations, analytical protocols, reproducible methods |
|**Publication-related materials** | Code, methods, and supporting files associated with scientific publications |
|**Documentation and guides** | Standard Operating Procedures (SOPs), protocols, technical guides, training materials, reports |
|**Models and simulations** | Hydrological models, ecological models, predictive models |
|**Tools and applications** | Utilities, internal applications, data management tools |

### What should not be uploaded on GitHub
&nbsp;&nbsp;&nbsp;GitHub is not intended to replace our existing systems for storing large datasets, general administrative documents, or sensitive information. **In other words, GitHub is not a general-purpose file storage or backup service.** It's particularly valuable for maintaining organized, versioned resources.

&nbsp;&nbsp;&nbsp;Avoid uploading:
* **Sensitive or confidential information:** Files containing sensitive or confidential information such as passwords, API keys, credentials, personal information, or other restricted materials. 
* **Large datasets or files:** These are generally better suited to specific scientific data repositories (e.g., EDI), organizational storage systems (e.g., SharePoint), or your own personal laptop.
* **General documents:** General files that do not benefit from version tracking are usually better suited to SharePoint.
* **Materials you don't have permission to share:** Check ownership, licensing, confidentiality, and applicable agreements before uploading.

---
Overall, you should ask yourself: 
* Would it be useful to keep a history of changes?
* Could I or someone else benefit from accessing this work in the future?
* Would having a central, documented version make this work easier to manage?

If you answered yes to any of these, GitHub may be a good place for your project.
