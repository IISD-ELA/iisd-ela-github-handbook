# IISD-ELA Repository Creation Guidelines

&nbsp;&nbsp;&nbsp;To ensure that our repositories are organized, easy to discover, and consistent, all new repositories should follow the guidelines outlined below. 

&nbsp;&nbsp;&nbsp;***You're strongly encouraged to use our automated GitHub project submission system, which handles all these requirements for you.*** See [Getting started with the IISD-ELA GitHub](../getting-started.md) for submission instructions, or [Appendix 2 - The IISD-ELA GitHub Project Submission System](appendices/appendix-2-auto-submission-system.md) for an optional, detailed explanation of how the system works.  

&nbsp;&nbsp;&nbsp;If you are already familiar with GitHub and prefer to create repositories manually, please ensure that your repositories meet the following requirements.

### 1. Use the IISD-ELA Template Repository
&nbsp;&nbsp;&nbsp;All repositories must be created from the template repository: [iisd-ela-repo-template](https://github.com/IISD-ELA/iisd-ela-repo-template). This repository is also pinned on the [IISD-ELA GitHub homepage](https://github.com/IISD-ELA). The instructions for using the template are included in the template's [README.md](https://github.com/IISD-ELA/iisd-ela-repo-template/blob/main/README.md).

### 2. Assign Topic Tags
&nbsp;&nbsp;&nbsp;Every repository must be tagged after creation. You can assign topic tags to your repository by clicking the gear icon next to the "About" section on the right hand side of your repository homepage. 

#### Requirements for *all staff*
- **Exactly one primary topic tag** must be assigned.
- **One to two secondary topic tags** must also be assigned.
- All assigned tags must come from the tables listed in [Appendix 4 - Topic Tags](appendix-4-topic-tags.md). Please ensure that tags are spelled exactly as they appear in these tables.

#### Additional rules for *owners of the IISD-ELA GitHub*
&nbsp;&nbsp;&nbsp;Only owners may create new topic tags. When creating new tags, follow these rules:
- Tags must be lower case
- Use singular nouns (e.g., `modelling` instead of `models`)
- Use hyphens to separate words (e.g., `data-workflow` instead of `data repository`)
- Avoid acronyms unless universally recognized (e.g., `gis` is universally recognized)
- Any new tag must be added to the topic tables in [Appendix 4 - Topic Tags](appendix-4-topic-tags.md) of this handbook.


## 3. Assign Collaborators and/or Teams
&nbsp;&nbsp;&nbsp;The repository creator is responsible for adding individuals or teams who will contribute to or maintain the repository. Collaboration can be assigned by **IISD-ELA GitHub Teams** (recommended) or **individual staff members**. For a list of our GitHub Teams, see the [Appendix 5 - Teams](appendix-5-teams.md).
